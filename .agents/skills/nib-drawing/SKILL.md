# Nib drawing

Nib is `:nib` (package `app.booxultimatum.nib`) on top of `:nib-engine` (pure Kotlin: strokes, brushes, layers, history, files) and the kit. [`docs/08-nib.md`](../../../docs/08-nib.md) describes the design as built and [`DESIGN.md`](../../../DESIGN.md) its visual world (cut-card instruments on a desk); this skill is the practical side. Nib's preview is verified on the owner's Note Air6 C for 0.2.0 (width at ×1, first stroke, cards excluded, marker colours). From 0.3 Nib writes like BOOX's own apps on `kit:ink`'s framework ([`docs/09-ink.md`](../../../docs/09-ink.md)); Diagnostics › Lab is how to check each new display call.

## Architecture in one breath

- `MainActivity` sees every pen event first and hands stylus hovers and touches to `PenRouter`, which forwards them to the surface on screen (`CanvasView` or `ProbeView`). That is how the canvas knows the pen is over Compose controls, which it never sees (`InkCanvasController.Target.Controls`); every control is excluded from the preview all the time, in multi-region mode, so nothing pauses over them.
- The floating controls lie over the full-bleed canvas, so the canvas can't tell them apart by its own bounds: each control records its window rectangle in `PenShields` (`Modifier.penShield`) as it's laid out, and `CanvasView.containsScreenPoint` excludes those areas. Any new control over the canvas needs `penShield`, or the pen over it will draw through it on the tablet.
- Nib's design system lives in `ui/studio/`: tokens (`Studio`, `StudioType`), `Modifier.slab` (the hard-shadowed card), `StudioKey`, `Pill`, `SlabButton`, `ValueChip`, `Toggle`, `Segmented`, `ChoiceTile`, `StudioSlider` and `QuickSlider` with their math in `ValueScale`, `FloatingPanel` with `PanelState` and the pure `PanelPlacement`, the `EntryBar`, `EnginePicture` (engine-drawn pictures, off the main thread and cached in `Samples`) and `StudioGlyphs`. Don't use or restyle `:kit:ui`'s components in Nib; the hub owns those.
- `kit:ink`'s `InkCanvasController` (pure Kotlin, JVM-tested in the kit) is the choreography: one hold per writing session, released at breaks. Nib's side of it is in `CanvasView`, `ProbeView` and `pen/` (`RevealPolicy` for Auto, `PenParts`, `PanelKind`), tested by `CanvasChoreographyTest`. One `InkSession` exists per process (`NibPen.session`); `InkGuard` (attached in `NibPen.start`) undoes what a killed process left.
- **Every release is a break the owner can see**, since the controller switches update schemes each time. Don't add a release to a code path that runs per stroke. Report breaks with `releaseNow(reason)` or a block, and let `frameShown()` gate them.
- **Anything that changes on screen during a hold is invisible** until a release, unless it's pushed. Pills declare what they show so `Host.pushControls` can push just the changed ones; a new control that changes while the pen writes needs the same.
- Preview colour for the Marker style goes through the engine's `MarkerPreview` (Settings › Display preview): the display drops translucent colours but greys, so it's opaque colour by default or a half-alpha grey. `BrushSpec.hardwarePreview(...)` takes it, along with the zoom and the turn, and returns the style parameters too.
- **Ink that matches the preview.** Wherever a preset becomes ink, use `preset.spec().inkAt(viewScale)`: the canvas (`Purpose.Ink`), `Samples.sCurve` and `Samples.through` (at 1), the Diagnostics bands (at 1) and the Brush settings dot. It pads the fountain pen's ink by the 3 screen px the display's fountain style adds, with its floor and speed on screen, turns the pencil's width into its stipple stamp's diameter (`Stipple.diameter` of exactly what the display is sent), and returns every other brush unchanged. The display is always sent the nominal spec's width: never pass an `inkAt` spec to `hardwarePreview` or `PreviewPolicy`, and never apply `inkAt` twice.
- **The stipple pencil** (`BrushKind.Pencil`, id `stipple_pencil`, `render/Stipple.kt`) is BOOX's charcoal v2 ink as penlab measured it: 1-bit, a fixed page threshold below the pressure, stamps of 1.16w + 5 screen px. Every `RenderSink` implements `stipple`; the sink works the pixels out on its own grid from its matrix (`CanvasSink` reads the canvas's matrix and draws each pixel back as an unantialiased square one device pixel wide), so the dots stay screen pixels at any zoom. That's why `TileCache.appendStroke` draws stipple strokes into each tile directly instead of recording a `Picture` in document pixels, and `DabRecording` treats them as general. The old pencil is `BrushKind.GrainPencil`, still id `pencil` so old strokes read as it; `BrushKind.retired` keeps it out of the catalogue and `BrushPreset.decode` moves slots holding it to the new pencil. Opacity and width-from-pressure are hidden for stipple brushes in Brush settings; tilt (`BrushTune.tiltScale`, key `ts`) is offered for every brush whose defaults tilt, and reaches the display as the charcoal styles' `tiltScale`.
- **Only variations the preview can show.** The owner's rule since 2026-10-07: a pen may differ from BOOX's own only in what its display style also draws (width, colour, the charcoal styles' tilt scale, the fountain style's sensitivity and smoothing, the square pen's angle). Taper, speed thinning, a chisel nib on a round style, grey or translucent ink on a 1-bit style all make the ink differ from the preview, which the owner sees as "not alike". Don't add one without a style that previews it; the brush pen and highlighter lost theirs in 0.3.0-test.8 (old strokes keep them, since every brush field is stored per stroke).
- **Comparing Nib's ink with BOOX's:** run penlab for the pen (`tools/host/penlab`), composite its stamps or points on the PC, render the same strokes with the engine's `SoftwareRaster` from a throwaway JVM test that writes PPMs, and put the two side by side; the 2026-10-07 session did this for the pencil (scripts in its session folder, not the repo).
- **Releases wait for SurfaceFlinger's own word** that it has the frame with the last stroke: `FrameLatch.watchNextFrame` hands the window a transaction with a committed listener. Register it when the stroke lifts, before the commit invalidates: `ViewRootImpl` gathers such transactions just before it draws, so one handed over from `onDraw` rides on the next frame instead. The listener API is Android 13 (API 33, lint's `NewApi` catches it); older devices fall back to the vsync after drawing. Each hold's Info log line counts the reports (`latched`).
- **The eraser end and the controller.** A merely paused session resumes at the next `down()`, so anything that must keep the preview off through a touch (the eraser end when its display preview is off, a quiet tool) is a `block`, not a pause. The kit's `hover(eraser = true)` blocks for that reason.
- **Two views, one session.** The editor and a Diagnostics page can swap on screen with the leaving one closing the shared session just after the arriving one attached; both retry opening once after attaching.
- `CanvasView` turns MotionEvents into the engine's `StrokeBuilder` samples, commits through `EditorSession` (the engine's `History` plus the active layer), and draws the page from `TileCache`.
- `EditorSession` sends every history event to `AutoSaver` (one background thread: journal append and sync, compaction) and to the canvas (tile updates).
- `OpenSessions` keeps a drawing open while its editor is anywhere on the back stack.

## Pitfalls already met

### Redesign (the floating studio)

- **The `create` file tool writes CRLF on this machine.** Normalise with a script over `nib` and `nib-engine` only. Never run a normaliser over the repository root: it once rewrote `captures/` (git-ignored, the owner's device data) and several tracked docs from CRLF to LF; the tracked ones came back with `git checkout`, the captures by turning LF back into CRLF, but any byte-order mark they had is gone.
- **`[IO.File]::ReadAllText` uses the process's directory, not PowerShell's location.** Pass absolute paths. Long here-strings also overflow the command line (`os error 206`); write big files with the file tool.
- **Don't write Compose state during composition.** A `mutableStateMapOf` filled by `getOrPut` while composing loops; `PanelState` keeps its pins and places in plain maps with a `revision` counter it bumps on writes.
- **Place panels in the same layout pass.** Measuring a panel, then moving it from `onSizeChanged`, costs a second frame, which is a second refresh on e-ink. `FloatingPanel` is a custom `Layout` that measures and places at once; what the placement reads (drag, saved spot, anchor) is state read in composition or placement, so a change relays out without recomposing.
- **Touches pass through a full-size layout with no pointer input** to the `AndroidView` below, and any `pointerInput` on a card stops them. Panels keep a pass-through full-size `Layout` over the canvas and put a no-op pointer reader on the card itself.
- **Turning the page without re-rendering.** `Viewport.unrotated()` places the tiles upright and `Viewport.turn()` turns the canvas once; tiles are drawn without antialiasing so neighbours meet without seams at any angle. Single-axis helpers (`toViewX(x)`) are gone: every mapping takes both coordinates.
- **Selection edits re-render their tiles at once** (`TileCache.renderNow`); left to the worker, the stale tiles showed the strokes back at their old place for a frame or two.
- **A digitiser keeps reporting a resting pen.** A timer restarted on every sample never fires while the pen rests; `HoldDetector.move` says when the pen really moved, and only that restarts the wait (the straight line).
- **Compose can hang a label on a child of the clickable node.** A `.semantics {}` placed after `.clickable` showed up in the accessibility tree as a separate, unclickable child. Put `semantics(mergeDescendants = true)` before `clickable`; the tests climb to the nearest clickable or editable node anyway.
- **An open unpinned panel blocks the session.** The pen's next touch on the canvas closes it and doesn't draw (`onCanvasTouch`); a pinned panel doesn't block, only the pen over it pauses.
- **The emulator is shared** and goes offline when the other agent restarts it; `adb devices` empty means wait and retry, not a Nib problem. Its app data survives the restart, but a drawing's thumbnail is as of its last snapshot, so one killed mid-edit shows blank on the shelf until it's opened and left again.

### Nib 0.1

- **The View inside Compose isn't clipped.** `canvas.drawColor` in an `AndroidView`'s `onDraw` flooded the whole window, toolbar and status strip included. Clip to the view in `onDraw` and put `clipToBounds()` after the padding on the `AndroidView`.
- **Keep the AndroidView at one place in the composition.** Switching between a `Row` and a `Column` for landscape and portrait recreates the view, losing the viewport, tiles and session. The editor uses one `Box` with padding instead.
- **A constructor parameter shadows the property in `init`.** `EditorSession`'s history listener read `document` (the constructor argument, the drawing as opened) instead of the live one and reset the active layer after every stroke. Name constructor arguments differently from the properties.
- **Android 16 ignores orientation requests on large screens** for targetSdk 36 apps. Instrumented tests rotate with `UiAutomation.setRotation(ROTATION_FREEZE_90)` and restore `ROTATION_FREEZE_0`; `requestedOrientation` does nothing on the Note Air6 C emulator.
- **PorterDuff MULTIPLY on a transparent tile paints nothing.** Use `BlendMode.MULTIPLY` (API 29), which is the separable W3C multiply the engine means.
- **Android sends a hover exit just before every touch.** Pausing on hover exit lost the start of quick first strokes, so the session no longer pauses on hover exit at all: it pauses when the pen hovers over a control or is blocked, and it opens drawing unless something blocks it.
- **Never let frames through while the pen touches.** Deferred: blocks, preview changes, and the swap of a previous stroke when a new one starts quickly (both are swapped once, after the second lift).
- **Many digitisers report zero pressure on the lift.** The last point keeps the pressure before it.
- **A stroke's bounds overstate where it inks.** A long diagonal's box covers many tiles it never crosses; `TileCache.reaches` tests segments against the tile before allocating or replaying.
- **Textured strokes are thousands of dabs.** Replaying a whole charcoal stroke into each of its tiles cost 60 to 75 ms per commit on the emulator; `DabRecording` replays each tile's own dabs (about 50 ms), and the worker does the same for background renders (a 70-tile document went from 1.1 s to 0.6 s). `TileCache.DAB_KINDS` is derived from the engine's `BrushKind.rendersAsDabs` (`DabRecordingTest` checks it against the renderer).
- **Bitmaps dropped during a frame may still be drawn by it.** Released tile bitmaps go to a graveyard and reach the reuse pool at the next frame.
- **Threads.** `History` and `DocumentIndex` are main-thread only; the tile worker and the saver read immutable `Document`, `Layer` and `Stroke` snapshots only.
- **`python -` with a piped here-string can start an interactive Python** on this machine and flood the output; write scripts to a file in the session folder and run them.
- **`adb shell input` can't hover and can't draw a closed loop in one gesture.** `input stylus motionevent DOWN|MOVE|UP x y`, several in one `adb shell` command, draws curves; loops, hover and multi-touch are tested with instrumented tests instead. In landscape the emulator's taskbar sits at the bottom, so a tap there opens another app.

## Adding a brush end to end

1. In `:nib-engine` (coordinate if another agent works there): add the `BrushKind` with a stable `id`, its `BrushSpec.widthRange` and `BrushSpec.defaults` (including its `Preview` style), its place in `BrushCatalog.kinds`, its rendering mode (`BrushKind.rendersAsDabs` for a dab brush, `usesNib` for a flat nib) and its texture in `StrokeRenderer.texture`. Add engine tests.
2. In `:nib`: add it to a `BrushGroup` in `brush/Presets.kt` (the test `everyNonEraserBrushSitsInExactlyOneGroup` fails otherwise), a label in `ui/Names.brush` and `res/values/strings.xml` (`brush_<id>`), and, for a new texture, a branch in `CanvasSink.dab` and a bitmap in `DabTextures`.
3. If its firmware style is unverified, nothing more is needed: `PreviewPolicy` uses the engine's verified fallback and its tile in the Brushes panel says so (≈). Once a style is verified on the tablet (Diagnostics › Styles, with the log as evidence in `knowledge/experiments.md`), flip `HardwareStyle.verified` in the engine.
4. Run `.\gradlew.bat :nib-engine:test :nib:testDebugUnitTest`, then draw it on the emulator in both orientations and check its tile's sample and the Brush settings pages it gets (texture for dab brushes, the nib dial, speed).

## How to test

- **JVM:** `.\gradlew.bat :nib:testDebugUnitTest`. `PenControllerTest` drives the controller with a fake `PenDisplay` and a hand-run `PenScheduler`; extend it for any change to the session policy.
- **Emulator:** `adb devices` must list only `emulator-5554` (AVD `NoteAir6C`, no Boox firmware, so the session is `Unavailable` and Nib draws in software). Build and install with `.\gradlew.bat :nib:assembleDebug` and `adb -e install -r nib\build\outputs\apk\debug\nib-debug.apk`; `adb -e shell input stylus swipe x1 y1 x2 y2 400` draws a line. Screenshots with `adb -e exec-out screencap -p > <file>.png` into the session folder, scaled down with PIL before viewing. Rotate with `settings put system accelerometer_rotation 0` and `user_rotation 1` (landscape) or `0`; put it back to portrait afterwards.
- **Instrumented:** `.\gradlew.bat :nib:connectedDebugAndroidTest` (set `$env:ANDROID_SERIAL = 'emulator-5554'`). `StudioEditorTest` covers the redesign (turned page, Reset view, lasso, typed values, eyedropper, straight line, shields, exports, a 0.1-style drawing) and finds and presses controls through `uiAutomation.rootInActiveWindow` by their content descriptions, typing with `ACTION_SET_TEXT`; no Compose test library is needed. `EditorTest` opens a drawing straight into the editor with `MainActivity.EXTRA_OPEN_DRAWING`, finds the canvas by `R.id.nib_canvas`, and dispatches stylus MotionEvents (tool type `STYLUS`, source `SOURCE_STYLUS | SOURCE_TOUCHSCREEN`, pressure) to it, or injects them through the window with `UiAutomation.injectInputEvent`. It resets the tool state in `@Before`. Running it uninstalls the app afterwards, so drawings made by hand on the emulator are lost.
- **The tablet:** only the owner draws there. Ship a test build on the test channel; the owner runs Diagnostics (every probe band answered), then About › Share logs. Read the `nib.probe` answers and the `nib.pen` stroke summaries (`previewed`, `held`, `swap ms`, `watchdog`) from the zip.
- **Nib's own side on the tablet, without the owner:** `adb shell input stylus swipe x1 y1 x2 y2 ms` reaches Nib as a stylus at pressure 1 (never the display's preview, which reads only the real pen), so ink widths (screenshot a Diagnostics band and count dark pixels), holds and frame reports (`nib.pen hold … latched=N` at Info) can be checked. Draw in Diagnostics, or in a throwaway drawing you delete afterwards: the shelf's Delete is a `ConfirmButton` armed for 4 s, so send both taps in one shell call (`input tap X Y; sleep 0.8; input tap X Y`). Read the owner's pens from the UI tree (`Pen 1: Pencil, 6 px`) and their learnt pressure from Diagnostics › Match preview before choosing defaults for them.
- **Logs to look for:** `nib.pen stroke` (one per stroke, with `commit ms`), `nib.render tiles rendered` (per batch), `nib.doc drawing opened` (`replayed`, `stop`, `truncated`) and `compacted`.
